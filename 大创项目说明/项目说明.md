# 智能植物养护系统（软硬件结合）项目说明

> 大创项目选题说明文档 · 计算机专业 大一
> 状态：核心硬件已采购，进入调试；一期采用手机 Web。当前任务以《执行计划.md》为准。

---

## 1. 项目名称

**智能植物养护系统**（暂定名，正式名称可结合老师意见调整）

一句话概括：**面向宿舍 / 家庭场景的智能植物养护系统**——通过传感器实时感知土壤湿度、光照、温湿度等环境数据，结合本地智能网关进行判断与图像识别，自动完成浇水等养护动作，并通过小程序 / Web 远程查看和控制，实现"不会养也能养活"。

---

## 2. 项目背景与问题

大学生和年轻上班族普遍有养植物、养多肉的意愿，但实际养护中存在几个普遍痛点：

1. **不知道该浇多少水、什么时候浇**——凭感觉浇水，要么涝死要么旱死。
2. **节假日 / 寒暑假没人照看**——放假回家，植物无人浇水。
3. **缺少数据反馈**——植物"不会说话"，出问题（缺水、光照不足、温度不适）时人往往后知后觉。
4. **市面产品割裂**——要么是纯硬件（定时浇水器，不智能），要么是纯 App（只提醒不执行），缺少"感知 + 判断 + 执行 + 远程可控"的完整闭环。

本项目希望做一个**低成本、可扩展、面向学生场景**的智能养护系统，把感知、决策、执行、交互整合到一起。

---

## 3. 项目目标

### 核心目标（一期）

- 实现对**土壤湿度、环境温湿度、光照强度**的实时采集。
- 基于阈值 + 简单规则，实现**自动浇水**（水泵 + 继电器控制）。
- 提供**小程序 / Web 端**，可远程查看实时数据、历史曲线、手动控制浇水。
- 数据本地存储，支持历史查询。

### 扩展目标（二期）

- 接入摄像头，用图像识别辅助判断植物长势 / 病虫害。
- 接入本地 / 云端大模型 API，做养护建议（如"土壤偏干且温度高，建议加大浇水量"）。
- 语音播报 / 主动提醒能力。

> 说明：原计划中的"盲人 / 老人辅助"方向（语音播报、简化交互）作为**二期附加功能**保留，不在一期范围内，避免摊子铺太大。

---

## 4. 技术方案

### 总体架构（端 - 网 - 云 - 用）

```
[感知执行端 ESP32]  ←→  [本地智能网关 Orange Pi 4 Pro]  ←→  [小程序 / Web 用户端]
   读传感器                 跑 Linux + Python                    查数据 / 下发控制
   控水泵继电器             存数据 / 图像识别 / LLM API
        |                            |
        └────── WiFi / MQTT ─────────┘
```

### 各层职责

| 层 | 硬件 / 技术 | 职责 |
|---|---|---|
| 感知执行端 | **ESP32**（MicroPython） | 采集土壤湿度、DHT11/22 温湿度、光照（BH1750）；驱动继电器 + 小水泵；通过 WiFi 上报数据、接收控制指令 |
| 本地智能网关 | **Orange Pi 4 Pro（4G）**（官方对应型号 Ubuntu） | Mosquitto + FastAPI + SQLite；图像识别和 AI 后置 |
| 用户端 | **手机 Web（HTML/CSS/JavaScript + Chart.js）** | 一盆植物实时数据、曲线、受限手动和自动控制；微信小程序后置 |
| 通信 | MQTT | 端 ↔ 网关的消息通道，主题划分如 `plant/{id}/sensor`、`plant/{id}/cmd` |

### 关键技术选型理由

- **ESP32 而非 Arduino Uno**：ESP32 自带 WiFi，能直接联网上云，价格更低（约 20 元），是一期的主控。
- **MicroPython 而非纯 C**：复用团队已有的 Python 基础，学习曲线平缓；团队 C 语言基础可作为底层兜底。
- **Orange Pi 4 Pro 4G**：性价比高、可跑完整 Linux，适合跑 Python 服务、数据库、图像识别；4G 内存足够本项目的负载。
- **数据存本地 + 可上云**：一期先做本地闭环（网关 + 局域网 Web），降低对公网服务器和备案的依赖；二期再考虑上云。

---

## 5. 创新点

1. **端-网-云完整闭环**：不是单点硬件或单点 App，而是"感知 → 决策 → 执行 → 交互"完整链路。
2. **本地智能网关**：把"聪明"放在本地（Orange Pi），即使断网也能本地决策和执行，比纯云方案更稳、更省流量。
3. **面向学生场景**：宿舍 / 出租屋 / 小阳台，成本低、体积小、可复制。
4. **可扩展性强**：架构上预留图像识别、大模型、语音的接入点，二期功能可平滑叠加。
5. **软硬件协同学习价值**：项目同时覆盖嵌入式（ESP32 / 传感器 / 电路）、后端（Python 服务 / 数据库 / 通信协议）、前端（小程序）三块，对大一团队是很好的完整工程训练。

## 6. 竞品与差异

| 类别 | 代表 | 局限 | 本项目差异 |
|---|---|---|---|
| 校园聚合小程序 | 课表 / 学分 / 生活服务类 | 偏信息查询，不涉及硬件、不涉及自动执行 | 本项目是"硬件 + 软件 + 自动执行"闭环，不在同一赛道直接竞争 |
| 已停维护的校园小程序 | — | 功能有价值但无人维护，说明需求存在、供给缺失 | 不与它正面抢功能，而是做"实体养护"这一新场景 |
| 市面智能花盆 | 定时浇水器、智能花盆 | 多为纯硬件、封闭、不可扩展、价格偏高 | 开放架构、低成本、可二次开发、可加 AI |
| 纯提醒类 App | 浇水提醒 App | 只提醒不执行 | 我们直接驱动水泵执行，可远程 |

**结论**：校园聚合小程序赛道已拥挤，本项目不进入该赛道；本项目属于"软硬件结合的物联网养护系统"，是差异化方向，入局合理。

## 7. 团队分工（4 人：3 软件 + 2 硬件，负责人跨软件与硬件）

| 角色 | 人员 | 主要职责 | 当前技能 |
|---|---|---|---|
| 负责人 / 软件主力 + 硬件兼 | 本人 | 项目统筹、后端 / 网关服务、小程序；硬件侧兜底与把关 | Python 基础 + vibecoding |
| 软件 A | 同学 B | 小程序前端、数据可视化、与网关接口联调 | 与负责人配合 |
| 软件 B | 同学 C | 网关后端服务、数据库、MQTT 通信（与负责人配合） | 与负责人配合 |
| 硬件 | 同学 D | ESP32 主控程序、传感器接入、电路连接、执行器调试 | C 语言基础 |

> 配置说明：软件侧 3 人（负责人 + A + B）保证小程序与服务端推进；硬件侧 2 人（负责人 + D）负责感知与执行链路，硬件环节由 D 主做、负责人兜底。

### 关于"C 语言人手不足"的影响评估

若团队中 C 语言人手不足，由多一个 Python 基础的人补位：

- **一期几乎无影响**：ESP32 用 MicroPython 开发，主控逻辑用 Python 即可完成，不依赖 C。
- **潜在短板**：如果未来遇到需要写 ESP32 底层驱动、性能敏感的 C 模块，或调试硬件寄存器级问题时，纯 Python 背景会比较吃力。
- **应对方式**：由负责人（本人）兼学 C / 了解硬件底层作为兜底；二期若确实需要 C，可再引入一位 C 背景成员或请老师指导。

## 8. 实施计划

团队每人每周 2–3 小时，按 16 个有效工作周推进，考试周顺延：1–2 周开机和模拟软件；3–4 周采集标定；5–6 周真实数据；7–8 周限时手动控制；9–10 周自动规则；11–12 周故障验证；13–14 周连续试运行；15–16 周对照实验与交付。

首次使用对应型号的官方 Ubuntu 桌面镜像，借显示器配置网络，之后 SSH；默认密码首次登录后修改。继电器输入兼容、传感器电平、水泵流量与停泵保护须实测，不能仅凭商品标题判定。

详细任务、当前代码范围及验收条件见 [执行计划.md](执行计划.md)。控制接口在硬件验证前锁定，模拟演示不代表实物已通过验收。

## 10. 风险与应对

| 风险 | 说明 | 应对 |
|---|---|---|
| 硬件调试受挫 | 传感器 / 水泵 / 电路接线出错 | 先在面包板上单独验证每个元件，再整合；预留备件 |
| Orange Pi 踩坑 | 系统刷写、外设驱动、镜像适配问题 | 连续三个调试时段无进展，调整排查路径；软件先在电脑开发，不因一次失败重买主板 |
| **退路 1** | 先用现有电脑作临时网关；确认主板故障后才考虑其它 Linux 板，采购另行核价 | 提前确认货源与价格 |
| **退路 2** | 网关环节整体后置，先做 **ESP32 + 云端**（ESP32 直接把数据发到云 / 本地电脑），后续再加本地网关 | 架构上保留这种切换空间 |
| 团队学习曲线 | 大一团队首次做完整工程 | 拆小任务、阶段验收、每周同步；老师定期指导 |
| 时间冲突 | 课业、考试挤占时间 | 阶段留缓冲；关键节点（单点验证、闭环）优先保 |
| 预算 | 硬件总价超预期 | 单价 ≤ 500 元是老师约束；整套控制在 600–900 元内 |
