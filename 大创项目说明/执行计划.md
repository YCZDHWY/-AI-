## 0. 采购完成状态

**已采购（核心链路）**

- 本地网关：Orange Pi 4 Pro 4G + 5V3A Type-C 电源
- 感知执行主控：ESP32 开发板（type-c + 数据线）
- 传感器：电容式土壤湿度 ×2、DHT11 温湿度、BH1750 光照
- 执行器：1 路继电器（高电平触发）、5V 潜水水泵（带 USB 头）、6mm 硅胶水管
- 开发配件：面包板套装（含电源模块 + 跳线）、杜邦线（公对公/公对母/母对母）、TF 卡 32G A2 + 读卡器
- 供电：绿联双口 5V2A 充电头（水泵/备用）

**暂不采购（第三笔扩展，核心跑通后再说）**

- CSI / USB 摄像头、USB 免驱网卡、花盆 + 营养土 + 植物

## 3. 阶段 1：立项与开箱（第 1–3 周）

**目标**：网关硬件跑起来，团队补齐基础认知。

### 3.1 Orange Pi 到手开箱（负责人主导）

1. **选镜像**：官方下载页选 **Ubuntu**（优先 Server 无桌面版），不选 Android。
2. **烧录**：TF 卡用读卡器插电脑 → balenaEtcher → 选 `.img` → Flash → 校验变绿 → 拔卡插板子。
3. **首次启动**：插卡 + 5V3A 电源上电。红灯常亮=通电，绿灯闪=运行。**第一次开机会自动扩容，等几分钟别拔电。**
4. **登录**：账号 `orangepi` / 密码 `orangepi`（输密码屏幕不显示，正常）。
5. **连 WiFi + SSH**：与电脑同一 WiFi，电脑 SSH 登录板子 IP，实现无屏开发。

> 供电提醒：长期跑用原配 5V3A 最稳；66W PD 头可应急点亮，但别多口分电。

### 3.2 团队基础学习（并行）

- 硬件 A/B：ESP32 + MicroPython 点灯、读一个传感器（先拿湿度传感器练手）。
- 软件 B：小程序开发基础、了解 MQTT 是什么。
- 负责人：Python 后端基础、MQTT 概念。

**阶段验收**：Orange Pi 刷进系统 + 连上 WiFi + Python 能跑 → 通过。
**卡住退路**：超 3 天不通且换镜像/外设无效 → 见第 6 节退路。

---

## 4. 阶段 2：单点验证（第 4–6 周）

**目标**：把"感知"和"执行"两件事各自单独跑通，不急着连网关。

### 4.1 感知链路（硬件 A 主做）

- ESP32 用 MicroPython 读土壤湿度、DHT11、BH1750。
- 数据通过 WiFi 发到电脑（先用简单 HTTP 或 MQTT 都行）。
- 电脑端能收到并打印数值。

### 4.2 执行链路（硬件 B 主做）

- ESP32 控继电器 → 继电器通断水泵。
- ⚠️ **水泵必须独立供电**（走自己的 5V2A / USB 电源），继电器控制通断，且**继电器与 ESP32 共地（GND 接一起）**，否则会重启或烧板。
- 验证：能远程/定时让水泵出水、停水。

### 4.3 联调准备

- 固定 MQTT 主题命名，如 `plant/{id}/sensor`、`plant/{id}/cmd`。

**阶段验收**：电脑能收到传感器数据 + 水泵能被 ESP32 控制出水。两点各自独立通过即可。
**卡住退路**：某类传感器读数异常 → 先换一个备用（湿度买了 2 个）；水泵/继电器问题优先查共地和独立供电。

---

## 5. 阶段 3：网关搭起（第 7–9 周）

**目标**：Orange Pi 成为"数据中枢"，能收、能存。

- Orange Pi 上装 Python 环境 + MQTT Broker（如 Mosquitto）。
- 写一个 Python 服务：订阅 ESP32 数据 → 存入 SQLite。
- 保留一个简单查询接口（本地能读到最近数据）。

**阶段验收**：ESP32 发的数据，能在 Orange Pi 数据库里查到记录。
**卡住退路**：Orange Pi 跑服务吃力 → 先用电脑临时当 broker 验证逻辑，再迁回板子。

---

## 6. 阶段 4：闭环打通（第 10–12 周）⭐ 核心里程碑

**目标**：端到端自动浇水跑通，这是项目成立的标志。

- 网关根据湿度数据 + 阈值规则，判断"该浇水了"。
- 网关下发命令（`plant/{id}/cmd`）→ ESP32 控继电器 → 水泵出水。
- 设定安全保护：单次浇水时长上限、两次浇水最短间隔，防止浇过头。

**阶段验收**：土壤干到阈值 → 自动浇水 → 湿度回升 → 停止，全程无人干预。
**卡住退路**：
- 退路 1：Orange Pi 主板级故障 → 换 Raspberry Pi 4（单价不超 500）作备胎，软件层几乎不改。
- 退路 2：网关整体后置 → 先做 ESP32 + 云端跑通链路，本地网关延后。

## 7. 阶段 5：用户端（第 13–15 周）

**目标**：手机能看、能控。

- 小程序展示：实时湿度/温湿度/光照、历史曲线。
- 支持手动浇水按钮、自动/手动模式切换。
- 网关对小程序提供数据接口和下发控制接口（负责人主导后端）。

**阶段验收**：手机上能看到实时数据 + 历史曲线，能手动触发浇水、切换模式。

---

## 8. 阶段 6：稳定与验收（第 16–18 周）

**目标**：跑得住、讲得清。

- 连续运行测试：让系统连续跑数天，观察是否稳定、有无崩溃/误动作。
- 补第三笔扩展（摄像头/AI 建议/语音）——**仅在前面都顺利、时间富余时做**，不影响结题。
- 整理文档：使用说明、技术文档、演示脚本。
- 准备结题/参赛材料。

**阶段验收**：连续运行稳定 + 完成一次完整现场演示 + 结题材料齐备。

## 9. 通用注意事项（全程有效）

1. **水泵独立供电 + 共地**：最容易被忽视、最致命的坑，接完先复查。
2. **先单点后联调**：每个环节单独跑通再串起来，别一上来就全连。
3. **阶段留缓冲**：课业、考试会挤时间，关键里程碑（阶段 4 闭环）优先保。
4. **每周同步 + 定期请老师把关**：别闷头做到最后才发现方向偏了。
5. **3 天验证线思维**：任何新硬件/新环境，3 天内跑不通就先找退路，不硬耗。
