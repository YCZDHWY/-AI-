# 智能植物养护系统 · 执行计划

> 更新于 2026-11-10。本文件为当前执行依据；原 Word 为早期选题稿，尚未同步。

## 当前执行计划：16 个有效工作周

采购完成，实物未调试。4 人每人每周 2–3 小时；第一版一盆植物、手机 Web、局域网访问，无硬性截止，考试周顺延。摄像头、AI、语音和微信小程序后置。

| 人员 | 负责 | 交付 |
|---|---|---|
| 你，软件兼硬件 | 联调、控制规则、接线复核、协调 | 闭环、验收记录 |
| 软件 A | HTML/CSS/JavaScript、Chart.js | 手机页面、曲线、操作状态 |
| 软件 B | FastAPI、SQLite、Mosquitto | 接收、查询、控制接口 |
| 硬件 D | ESP32 MicroPython、传感器与水泵 | 接线表、采集与限时执行程序 |

3 软件 + 2 硬件为交叉职责，共 4 人。每人每周一个可验收任务，两次约 1 小时工作和 15 分钟同步；提交代码、操作说明和证据。你负责联通各部分，前后端由同学主做。

| 周次 | 工作 | 验收 |
|---|---|---|
| 1–2 | 官方对应型号 Ubuntu 桌面镜像、借屏配网、SSH；ESP32 刷 MicroPython；模拟页面和接口 | SSH/Python 可用、ESP32 可执行、模拟读数显示 |
| 3–4 | 逐个读土壤、DHT11、BH1750；干湿标定；存储 | 三类数据稳定，参考值有记录，模拟数据入库 |
| 5–6 | MQTT 上报、入库、Web 真数据 | 实时数据、24 小时曲线、离线和过期显示 |
| 7–8 | 继电器电平确认、USB 正线通断接线、流量测量、先本地再 Web 点动 | 到时停泵、执行反馈、不重启 |
| 9–10 | 阈值、短时浇水、等待渗透、间隔和累计上限 | 干燥才触发，手动同样受保护 |
| 11–12 | 断网、网关停止、拔传感器、重复命令、重启 | 无持续运行、无重复误动作、可恢复、有记录 |
| 13–14 | 连续 7 天试运行和修复 | 无失控，数据缺失和误动作可追溯 |
| 15–16 | 固定时长与湿度反馈对照、演示与材料 | 实际测量、完整演示、局限说明 |

对照实验尽量固定植物、土壤、花盆和光照，比较耗水量和湿度在目标区间的时间；条件不足做同一装置分时测试并说明局限，不凭演示宣称节水或成活率提高。

### 第一周领取任务

- [ ] 你：实物清点，借显示器键鼠，确认匹配显示线，准备 2.4GHz 固定热点。
- [ ] 软件 A：启动仓库手机 Web，提交四项读数、离线状态和手机截图。
- [ ] 软件 B：在电脑运行 FastAPI/SQLite，提供最新接口及重启后数据仍在的证据。
- [ ] 硬件 D：确认 ESP32 型号和引脚图、刷 MicroPython；向卖家确认继电器输入和传感器电平，提交接线草图。

首次借屏配置 WiFi，改默认密码，记录镜像版本、IP 和登录方法，再用一台电脑 SSH。热点先验证电脑与网关互访，再加 ESP32；另一台手机访问 Web。隔离时借路由器，不因此换主板。首次启动等扩容，不中途拔电。

当前仓库提供模拟数据软件起点和只读 ESP32 参考固件。水泵控制和自动规则尚未实现；不得将代码存在视为实物验收完成。第一周不连接完整水路，硬件受阻时软件继续用模拟数据；连续三个调试时段无进展再换排查路径。

### 接线与控制约定

- 5V 继电器不保证 3.3V 可触发；核实无 5V 回灌，不兼容则加驱动或换模块。
- USB 水泵需 USB 公母延长线或端子转接件，正线经 COM/NO 触点通断，电流不走 GPIO 或面包板跳线。MB102 不供水泵。
- 逻辑侧共地按具体电路；触点隔离的泵侧不必一律共地。双口充电头不同口仍可能共享电源，不等于隔离。泵的浪涌抑制按电机类型核实。
- 传感器输出不得超过 ESP32 输入电平；普通 ESP32 的土壤模拟量优先 ADC1。
- 先测流量，从约 1 秒点动开始，再定时长、间隔和日累计上限；断网、重启、异常数据默认停泵，本地计时不依赖网关。
- 每条命令唯一编号和时长，不 retained，拒绝重复或过期命令；有设备完成反馈才显示成功。
